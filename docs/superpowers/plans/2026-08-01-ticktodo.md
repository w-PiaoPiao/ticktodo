# TickTodo 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现对标滴答清单核心功能的安卓待办应用（Flutter + 坚果云 WebDAV 快照同步）。

**Architecture:** 本地 SQLite (sqflite) 为主数据源，Repository 层封装读写，Riverpod 状态管理。同步用"快照方案"：整库导出 gzip JSON 上传坚果云，打开 App 自动下载比较 revision，变更防抖 30s 上传，冲突按 id 合并取 updatedAt 较新者。四个底部导航视图（今天/最近7天/日历/全部）+ 左侧抽屉 + 设置页。

**Tech Stack:** Flutter, sqflite, Riverpod (flutter_riverpod), flutter_local_notifications, timezone, http, path_provider, shared_preferences, intl, archive (gzip)。

## Global Constraints

- Android 平台，minSdk 21+（flutter_local_notifications 要求 21+）
- 所有实体含 `deletedAt` 软删除字段（同步需要墓碑）
- 快照文件：坚果云 `TickTodo/todo_backup.json.gz`，内容 `{revision, tasks, subtasks, lists, tags, taskTags}`
- revision = 最近一次数据变更的 epoch 毫秒
- 冲突合并：时间差 < 5 分钟 → 按 id 合并取 updatedAt 新者；否则保留 revision 大者
- 网络/压缩操作必须放 `compute()` isolate
- 中文 UI 文案
- 测试命令：`flutter test`

### Task 5: 快照序列化与合并（纯 Dart 核心）

**Files:**
- Create: `ticktodo/lib/sync/snapshot.dart`
- Create: `ticktodo/lib/sync/snapshot_merge.dart`
- Create: `ticktodo/lib/sync/gzip_codec.dart`
- Test: `ticktodo/test/snapshot_test.dart`

**Interfaces:**
- `SyncSnapshot { revision, tasks, subtasks, lists, tags, taskTags }`；`toJson()/fromJson()`。
- `buildSnapshot(db) → SyncSnapshot`：读全表（含软删除）。
- `applySnapshot(db, snapshot)`：事务内 bulk upsert 全部实体。
- `mergeSnapshots(local, remote) → SyncSnapshot`：
  - 双方按 id map；`updatedAt` 新者胜；双方均有且均删 → 保留删除（取 updatedAt 大者）。
  - revision = max(local.revision, remote.revision)
- `gzipEncode(jsonStr) → List<int>` / `gzipDecode(bytes) → String`（archive 包，纯 Dart 可在测试中直接跑）。
- 注意：`updatedAt` 相等时以 remote 为胜（确定性）。

- [ ] **Step 1: 写 snapshot.dart + snapshot_merge.dart + gzip_codec.dart**
- [ ] **Step 2: 测试**：buildSnapshot→applySnapshot 往返无损；merge 各种情形（本地新/远端新/同 updatedAt/一边删除一边更新/新记录 union）；gzip 往返。

### Task 7: 同步编排与凭据存储

**Files:**
- Create: `ticktodo/lib/sync/sync_manager.dart`
- Create: `ticktodo/lib/sync/sync_settings.dart`
- Test: `ticktodo/test/sync_manager_test.dart`

**Interfaces:**
- `SyncSettings`（SharedPreferences）：`webdavUrl, username, password`、`lastSyncAt`、`setCredentials(...)`。
- `SyncManager(db, client, settings)`：
  - `Future<SyncResult> syncNow()`：下载远端快照 → 不存在则直接上传本地（revision 不变）；存在则与本地 build 的快照 merge → 本地与远端差异判断 → 需要则上传合并结果、否则仅本地应用。
  - `Future<void> scheduleAutoUpload()`：变更后调用，防抖 30s（Timer 取消重建），超时后 isolate 里 build+compress+PUT。
  - `revision` 更新规则：每次本地写操作后由 Repository 记录 `lastMutationAt`（内存），buildSnapshot 时若本地有比 snapshot 更新的变更则 revision 取 `max(snapshot.revision, lastMutationAt)`。
  - 错误：网络失败抛异常但内部吞掉并置 `lastError`，UI 读状态。
- 简化决策：syncNow 内直接 build 本地快照与远端比较——revision 相同且内容相同则跳过上传（跳过比较内容，只看 revision）。
- `SyncResult { uploaded, downloaded, merged, error }`

- [ ] **Step 1: 写 SyncSettings + SyncManager**
- [ ] **Step 2: 测试**（MockClient + 内存库）：首次同步（远端空→上传）、远端新→下载应用、本地新→上传、冲突→合并后上传、凭据持久化。
